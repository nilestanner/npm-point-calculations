## 2025-02-23 - Prevent Division by Zero resulting in NaN
**Vulnerability:** A missing check for zero distance in `findPointOnLine` resulted in a division by zero. This division by zero creates a `NaN` ratio, which propagates `NaN` into the X and Y coordinates. This `NaN` contamination can break data structures, invalidate rendering logic, or cause denial-of-service (DoS) if these invalid points trigger infinite loops or uncontrolled recursion in dependent systems.
**Learning:** Math functions that perform division using derived values (like Euclidean distance) are inherently risky when the inputs can result in a zero denominator. The logic incorrectly assumed start and end points would always be distinct.
**Prevention:** Always validate inputs or intermediate derived values before using them as denominators in mathematical operations. Return a safe, defined fallback (like the original starting point) when operations cannot be mathematically resolved safely.
## 2025-02-23 - Prevent Type Confusion and NaN Poisoning in Math Functions
**Vulnerability:** Core mathematical calculations accepted arbitrary objects without validating input types. By passing strings, NaN, or improperly formatted objects instead of properly typed numbers, the operations output `NaN`. This `NaN` propagation could contaminate downstream data structures, crash rendering contexts, or lead to Denial-of-Service if infinite loops depend on these numeric evaluations. Furthermore, the `...startPoint` spread operator allowed excess property propagation when zero distance was detected.
**Learning:** Pure math library functions are a critical attack surface for type confusion since JavaScript's loose typing can implicitly convert strings and objects in ways that silently fail by returning `NaN`. Downstream consumers often do not validate the output of these libraries.
**Prevention:** Implement strict boundary validation for all exported functions in utility libraries. Assert that parameters exist, possess correct primitive types, and are not `NaN`. Do not pass through unvalidated object structures using spread operators; reconstruct safely instead.
